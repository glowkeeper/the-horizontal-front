# 0.2.1 — Held the line, tidied the room

Status: public release, not a production release

A maintenance release. No new content, no rule changes: two defects reported
against the live `0.2.0` deployment, and a documentation-accuracy pass. Play it
at [thehorizontalfront.org](https://thehorizontalfront.org).

`1.0.0` remains reserved for a release meeting the [no-placeholders
invariant](../release-process.md), including human authorship of
identity-critical artwork. The gap described in
[0.2.0](0.2.0.md) is unchanged and is repeated below.

## What changed

**The hit feedback no longer depends on an emoji font.** `SOLIDARITY! ✊ 🛏️`
became `SOLIDARITY!`. The feedback is drawn as canvas text, so those glyphs
resolved through whatever emoji font the device happened to offer, or rendered
as empty boxes on a device carrying none — at the exact moment the game
congratulates the player. The project's own mark already exists for this job;
player copy is words. The README tagline lost the same glyphs.

`npm run check:policy` now rejects emoji in validated player-visible content, so
this cannot return a fourth time. The plain `✓` and `✕` marks the hit and miss
feedback use are ordinary text characters rather than emoji, and are unaffected.

**The focus ring is shown only to players using the keyboard.** The accept
control on the outcome screen took focus on arrival whatever the player was
using, so someone who tapped their way there was shown a red ring inside a
red-stroked panel, which read as a double border or a rendering fault rather
than as the keyboard's position.

Focus now follows the input actually in use: the control for a keyboard player,
the game surface for pointer and touch. It stays inside the game either way, and
the first Tab reaches the controls with the ring the player has by then asked
for. The ring is charcoal rather than red, so it cannot be confused with the
panel stroke it sits within.

Visible focus was not removed. It is a stated accessibility property of this
release, and a browser test now asserts both halves so neither can be fixed by
sacrificing the other. A one-frame window in which focus rested on the document
body during scene transitions was found and closed while fixing this.

**Documentation accuracy.** The engine and grammar documents described generic
mechanisms in one episode's furniture, named an engine field that no longer
existed, and described three semantic validation rules that were never
implemented. A contributor could have believed a class of composition error was
caught by the build when it was not. `AGENTS.md` now records which register each
document is written in.

## Unchanged from 0.2.0

Content, controls, rules, licensing and offline behaviour are unchanged. One
campaign, **The Monday Uprising**, containing one episode, **The Alarm**. The
controls, accessibility properties, licences and provenance recorded in
[0.2.0](0.2.0.md) apply to this release without amendment.

## Supported environments

The supported matrix is carried forward from `0.2.0` and is not widened:

- Desktop Google Chrome, keyboard and pointer, at 1280x720.
- Google Chrome on a Motorola Moto G84 5G running Android 15, touch input, in
  landscape and portrait.
- Audio-enabled play and muted play.

Other browsers, devices and Android versions may work. They are not claimed.

## Offline

The complete release remains static. Once its files are cached, play does not
depend on a backend, account, database, third-party API or any remote service
remaining available. `npm run test:offline` exercises this against the built
release rather than the development server.

## Known limitations

Carried forward from `0.2.0` and still true:

- The artwork is AI-generated under maintainer direction, with the copyright
  standing described in [0.2.0](0.2.0.md). Human refinement of Management and
  the protagonist is wanted and not done.
- The audio mix is a first pass, tuned by a maintainer working without a sound
  designer.
- Playtesting is one person, not representative players.
- Mobile screen readers, including TalkBack, are unevaluated.
- One Android device and one Chrome version were tested.
- Management's console is drawn slightly differently in each of the four poses,
  so nominally fixed apparatus shifts as they strain.
- Authoring a new episode means writing JSON by hand against the grammar
  reference. An authoring tool is planned and not built.

New in this release:

- Geometric validation of the resistance composition is not implemented. A skin
  whose authored states advanced the wrong end of its structure would be caught
  by review rather than by the build. This was previously described as
  implemented; the description was wrong, not the code.
